# フェーズ2（動画）技術検証レポート

調査日：2026年10月11日

## 結論（先に）

**「WebCodecs ＋ Mediabunny（MP4 を作るライブラリ）」を採用するのがよい**と判断しました。

- 映像：動画を1コマずつ取り出し → Canvas でフレーム・文字・効果を合成 → 端末のハードウェアで H.264 に圧縮
- 音声：元の動画の AAC 音声を**そのままコピー**（作り直さない）。モードBのイントロ分だけ開始時刻をずらす
- できあがり：MP4（H.264 + AAC）。iPhone の写真アプリ・Android のギャラリー・SNS でそのまま扱える形式
- 実時間より速く処理でき（30秒の動画を30秒待たなくてよい）、追加のダウンロードは約130KB（圧縮後）
- のちの Capacitor 版（iPhone の WKWebView、Android の WebView）でも同じ仕組みがそのまま動く見込み

ffmpeg.wasm は**使いません**（遅すぎる・重すぎる・ライセンスがストア配布と相性が悪い）。
MediaRecorder は「実時間でしか録れない・コマ落ちする」ため、使うとしても予備の手段です。

## 比較

| | WebCodecs + Mediabunny（採用） | MediaRecorder（予備） | ffmpeg.wasm（不採用） |
|---|---|---|---|
| iPhone Safari | iOS 16.4 以降で映像OK。音声の作り直しは iOS 26 以降（**コピーなら 16.4 以降でOK**） | iOS 14.1 以降で MP4 録画可 | 1スレッドのみ。メモリ不足の報告あり |
| Android Chrome | Chrome 94 以降で OK（H.264 はハードウェア） | Chrome 126 以降で MP4 録画可 | 1スレッドのみ（速くする設定は GitHub Pages では難しい） |
| Capacitor 版 iPhone | Safari と同じ（OSのバージョン次第） | 同左 | 速くする設定がほぼ不可能 |
| Capacitor 版 Android | Chrome と同じ | 同左 | 可能だが遅い |
| 追加の重さ | 約130KB（圧縮後） | 0 | 約10MB（圧縮後） |
| 30秒動画の処理時間（見込み） | 15〜90秒ほど（**実機で要確認**） | 必ず30秒以上（画面を開いたまま） | 20〜60分以上（見込み） |
| 音声 | 元の音声をコピー | 録音しながら合成 | 可 |
| 主な心配 | 端末によっては HEVC（iPhone の標準形式）を読めない／HDR 動画の色 | コマ落ち・画質の制御が弱い・途中で画面を離れると失敗 | 遅い・GPL ライセンス（App Store と相性が悪い） |

### 補足

- **iPhone で撮った動画（HEVC/H.265）の読み込み**：iPhone の Safari ではほぼ読める。Android の Chrome では端末によって読めないことがある（調査では6〜8割程度の端末が対応）。読めない場合は案内を出す
- **iPhone の HDR 動画**：明るさ・色が白っぽくなる可能性がある（資料が見つからず、実機確認が必要）
- **音声の時刻ずらし**：MP4 の「編集リスト」という仕組みで、イントロの間は無音にしている。SNS アプリがこれを正しく扱うかは実機で確認したい（ダメなら無音部分を作って入れる方法に切り替える）
- **フィルター**：1コマずつ CPU で計算すると重いので、本番では WebGL（GPU）で処理する予定
- **ライセンス**：Mediabunny は MPL-2.0（商用・ストア配布OK。ライブラリ自体を改変した場合だけ、その部分の公開が必要）

## 検証ページ（実機でのテスト）

調査だけでは実機の速度が分からないため、**スマホで実際に書き出しを試せるページ**を作りました。

- URL：https://huu69769.github.io/cheki/?lab=video
  （アプリの「このアプリについて・ライセンス」画面の一番下からも開けます）
- やること
  1. ページを開くと「この端末の対応状況」が表示されます
  2. 「動画を選ぶ」で 30 秒くらいの動画を選びます（iPhone で普通に撮ったものでOK）
  3. 「書き出してみる」を押します（モードB・9:16 が初期設定）。進み具合とキャンセルボタンが出ます
  4. 終わったら「再生して確認・保存」で、イントロ演出と音声を確認できます
  5. 「結果をコピー」を押して、その文章をそのまま送ってください
- できれば iPhone と Android の両方で、モードA・モードB を1回ずつ試してもらえると助かります

検証環境（開発用のパソコンのブラウザ。H.264 が使えないため VP9 で代用）では、
1080×1920・約10秒（イントロ1.8秒＋本編8秒）の書き出しが **13.4秒** で完了し、
映像294コマ・音声は 1.8 秒から開始、という正しい MP4 ができることを確認済みです。
スマホは H.264 をハードウェアで処理できるので、これより速くなる見込みです。

## 決まったこと（2026-10-11）

- モードは利用者が選べるようにする
  - モードA（入り込まない）：フレームの中で動画が再生される
  - モードB（入り込む）：止まった1コマのフレームから中へ入り込み、そのあと本編を画面いっぱいに再生する
- 動画の長さの上限は、ひとまず60秒（`MAX_VIDEO_SECONDS`）

## 本番の実装方針（ご判断をいただいたあと）

1. 動画を読み込み、長さが上限（`MAX_VIDEO_SECONDS`、いまは60秒）を超えたら案内を出す
2. 編集画面は写真と同じ部品（フレーム・文字・フィルター・効果・日付・スタンプ）を使う。プレビューは `<video>` を再生しながら Canvas に合成
3. モードB：動画の中から1コマを選ぶ画面（スライダーで探す）
4. 書き出し：比率（9:16 / 1:1 / 4:5）を選ぶ → 進捗とキャンセル → 仕上がりの確認画面で再生 → 保存・共有・編集に戻る
5. 非対応の端末（iOS 16.3 以前など）では、理由を表示する
