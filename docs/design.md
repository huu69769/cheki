# 設計のまとめ

## 方針

- Vite + React + TypeScript。描画は Canvas 2D
- サーバーなし・ログインなし。写真・動画は外部に送信しない
- 画面の切り替えは URL を使わず、アプリ内の状態で行う（GitHub Pages のサブフォルダでも、Capacitor のローカルファイルでも動くように）
- ビルドは相対パス（`vite.config.ts` の `base: './'`）

## 層の分け方

```
ui/        画面（React）。編集データを表示し、操作を core の関数に渡す
  ↓ 呼ぶ
core/      編集データ・描画・フィルター・履歴。UIにも端末にも依存しない
platform/  端末に依存する処理。インターフェース経由でだけ呼ぶ
```

### platform 層

| インターフェース | 役割 | Web版の実装 | Capacitor版（予定） |
|---|---|---|---|
| `MediaPicker` | 写真・動画を選ぶ／撮る | `<input type="file">` | @capacitor/camera など |
| `MediaOutput` | 保存・共有 | ダウンロード、Web Share API | 写真アプリへの保存プラグイン、@capacitor/share |
| `DraftStore` | 下書きの保存 | IndexedDB | IndexedDB のまま（必要なら @capacitor/filesystem） |

`src/platform/index.ts` で、どの実装を使うかを1か所で決めています。

### 描画エンジン（core/render）

- 座標はすべて **mm**。フレームの左上が原点
- フレームの寸法：ミニ 54×86、スクエア 72×86、ワイド 108×86（高さをそろえて、形を変えても文字の縦位置がずれないようにしている）
- `renderDocument(ctx, doc, photo, { pxPerMm })` が、画面表示と書き出しの両方で使う唯一の描画関数。拡大率（pxPerMm）を変えるだけで、見たままの仕上がりを高解像度で書き出せる
- 描く順番：フレーム（色・柄・紙の質感）→ 窓（写真 → 光漏れ → ビネット → 粒子）→ 日付 → 文字・スタンプ → （編集中のみ）選択枠
- フィルターは画素を直接計算（Safari の Canvas が `ctx.filter` に対応していない時期があったため）。画面表示用には長辺1600pxの写真にかけてキャッシュし、書き出し時は必要な解像度でかけ直す

### 編集データ（core/model）

`PhotoDoc` に、フレーム・写真の位置・効果・日付・文字やスタンプ（レイヤー）をすべて持つ。
写真そのものは持たず、下書きでは別に保存する。
データは変更のたびに新しいオブジェクトを作る（イミュータブル）ので、元に戻す／やり直しは「前のデータに戻す」だけで実現できる。

### 元に戻す／やり直し（core/history）

指でドラッグしている間やスライダーを動かしている間の細かい変更は、同じ「まとめ用キー」を付けて1回分の操作として記録する。

## フェーズ分け

| 段階 | 内容 |
|---|---|
| 1-1 | 読み込み＋フレーム（形・色柄）＋写真の位置・拡大・回転、元に戻す、下書き |
| 1-2 | 文字入れ |
| 1-3 | フィルター・粒子・ビネット・光漏れ・日付刻印・スタンプ |
| 1-4 | 書き出し → プレビュー → 保存・共有・編集に戻る |
| 2 | 動画（技術検証 → 判断をもらってから実装） |
